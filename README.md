# ETF PEG 实时分析工具

穿透 ETF 持仓，用**整体法**计算组合 PE 与归母净利润增速，得到 ETF 层面的 PEG。
全部数据来自**免费公开接口**，无需注册、无积分、无 API Key，仅依赖 Python 标准库。

## 快速开始

```bash
# 方式一（推荐）：双击  启动.bat ，服务起来后会自动打开浏览器
# 方式二：命令行
python run.py                    # 启动 Web 服务，并自动打开浏览器
python run.py --no-open          # 不自动打开浏览器
python run.py --port 9000
python run.py --cli 510300       # 命令行模式，直接输出单只 ETF 的 PEG
python run.py --cli 512480 --mode latest
```

> 运行 Web 服务的那个黑窗口**不能关**，关了服务就停了。

首次运行会拉取全市场行情（约 5900 只）与财报，耗时 10~60 秒；
之后走本地缓存与数据库：行情 2 分钟、财报与持仓永久保存（详见「本地数据库」）。

## 本地数据库（持久化策略）

数据**按可变性分层存放**，不变的数据写一次就不再重复下载：

```
etf_peg.db（SQLite，标准库自带，无需安装任何东西）
├── fin            历史财报      57,461 条 / 5 期      永久保存
├── holding        基金持仓      按 ETF×报告期         永久保存
├── report         研报盈利预测  14.8 万篇 / 4865 只   往年不变，当年每日增量
├── etf            ETF 名录      1316 只              每天刷新
├── stock_pe       个股每日 PE   按 日期×股票          永久保存（历史回填用）
├── etf_daily      PEG 每日快照  按 日期×ETF 追加      历史序列
└── holding_probe  持仓探活记录  控制回源频率
```

| 数据 | 是否入库 | 策略 |
|---|---|---|
| 历史财报 | ✅ 永久 | 过了披露截止日 + 7 天宽限期即视为**定稿**，永不重下；披露中的最新一期缓存 6 小时，命中缓存时再探活一次上游家数，有新公司披露就立刻重拉 |
| 基金定期报告持仓 | ✅ 永久 | 某期报告的持仓是既成事实；只有距上期报告超 95 天（可能出新报告了）才回源探活，且探活间隔 ≥12 小时 |
| ETF 名录 | ✅ 每天 | 变化很慢 |
| PEG 每日快照 | ✅ 追加 | 每成功分析一次就记一条当天数据，用于看趋势 |
| 行情价格 / PE | ❌ 不入库 | 每秒都在变，只在内存缓存 2 分钟 |

**实测效果**（5 只 ETF，清空数据库后连续跑两次）：

```
第 1 次   182 次 HTTP 请求   119~620s   回源抓取并写入本地库
第 2 次    60 次 HTTP 请求      10.9s   财报与持仓全部本地命中
                                       剩余 60 次全是实时行情（价格本就不该入库）
```

也就是说，除了每秒都在变的价格，**其他数据第二次起就是零网络请求**。
财报 5 期共 5.7 万条、持仓 8150 条，落盘后总共 7.7 MB。

查看与维护：

```bash
python run.py --store                     # 本地库状态
python run.py --history 510300            # 某只 ETF 的 PEG 历史序列
python run.py --backfill 510300 --days 250  # 回填历史（带进度条）
python run.py --init-pe                     # 全市场 PE 初始化（约 2 小时，可断点续传）
python run.py --sync-reports              # 同步全市场研报盈利预测（首次 3~5 分钟）
python run.py --clear-history 510300      # 清空某只 ETF 的历史快照
```

数据库文件 `etf_peg.db` 可随时删除，删了会自动重建（只是要重新下载一次）。

### 三个关键实现细节

**1. ETF 全持仓必须取半年报/年报**

监管要求基金**季报只披露前十大重仓**，只有半年报（6-30）和年报（12-31）才披露全部持仓。
所以 `fetch_etf_holdings()` 会依次尝试「今年半年报 → 去年年报 → 去年半年报」，
取股票数最多的一期；实在拿不到才退回季报前十大，并把 `full` 置为 `False` 交由上层警示。

实测：`510300` 默认请求只返回 10 只，指定 `year=2026&month=6` 后返回 **339 只**。

**2. 动态 PE 的取法**

`clist` 列表接口的 `f9`（市盈率动态）可直接批量取全市场；
单只可用 `stock/get?fields=f162`（市盈率 TTM，返回值需 **÷100**）。
工具用的是 `f9`，一次分页拉完 5900 只。

**3. 归母净利润用批量报表，不要逐只请求**

`RPT_LICO_FN_CPD` 单次可返回全市场某一报告期的归母净利润与同比：

```
PARENT_NETPROFIT  归属母公司净利润（元）
SJLTZ             净利润同比增长率（%）
TOTAL_OPERATE_INCOME / YSTZ   营业收入及其同比
```

逐只请求 5000 次要几十分钟，批量拉取只要几十秒。

## PEG 是怎么算的

### 为什么不能用算术平均

成分股里只要有微利股（PE=1000）或亏损股（PE<0），算术平均就被彻底带偏。
这里用**整体法**（中证/国证/Wind 的通行口径）：

```
PE_i    = 实时总市值 ÷ 该股「最新已披露」的 TTM 归母净利
增速_i  = 同一期财报构造的 TTM 同比          ← 与 PE 同源同期
PE_组合 = Σw / Σ(w / PE_i)                  w = 基金披露的持仓权重
G_组合  = Σ(w·净利润 TTM) / Σ(w·去年同期净利润 TTM) − 1
PEG     = PE_组合 / G_组合                  ← 仅 G_组合 > 0 时有值
```

**增速同样是全口径 + 持仓权重加权**：亏损股、负增长股全部计入，不做样本
筛选（旧口径只留 PE>0 且正增长，会把增速系统性抬高——013817 实测正增长
样本 +26.2%，全样本等权 −108.1%）。净利润是绝对金额，必须乘权重；不乘
权重等于假设每只成分股都 100% 持有，且对集中度高的组合失真严重。

`g_all` 保留为**等权简单相加**的对照（`Σ净利润 / Σ去年同期净利润 − 1`），
它与加权增速的差额反映**持仓集中度**（大权重股主导），而不是样本剔除。

### 扣非 PEG（与归母 PEG 并列的第二套口径）

机构对制造业更常用扣非口径（剔除政府补助、资产处置、公允价值变动等一次性
损益）。因此工具同时给出一套**独立的扣非体系**，两者互不替代：

```
扣非PE_i   = 实时总市值 ÷ 该股 TTM 扣非归母净利   （只算扣非 > 0 的股票）
扣非PE_组合 = Σw / Σ(w / 扣非PE_i)
扣非增速    = Σ(w·扣非TTM) / Σ(w·上年扣非TTM) − 1   （全口径加权）
扣非PEG     = 扣非PE_组合 / 扣非增速               （仅扣非增速 > 0 时有值）
```

- 扣非增速与归母增速**完全对称**：不筛样本、乘持仓权重；港股不披露扣非、
  A 股某期缺扣非时，用归母净利润顶上（与成分股明细的 † 一致）。
- 扣非 PE **只统计扣非 TTM > 0 的股票**——扣非为负的公司在扣非口径下没有 PE。
  因此扣非 PE 与扣非增速的样本天然不同：增速含负扣非股，PE 只含正扣非股。
- **亏损周期里「有扣非增速、没有扣非 PEG」是正常现象**，不是数据缺失。
- 分工：制造业/周期股看扣非；金融股与港股看归母（港股无扣非口径）。
  两者背离时（归母 PEG 便宜但扣非 PEG 缺失或很高），说明利润可能靠非经常性
  项目撑着。
- 数据边界：东财利润表接口的扣非金额可回溯至 2015 年，本地库首次命中历史
  期次时会自动补拉（`backfill_deduct`）；补拉失败冷却一小时后再试。

**PE 与增速共用同一期财报**，不会出现"PE 按旧财报、增速按新财报"的错配。
实测自算 PE 与东财 `PE_TTM` 完全一致（中际旭创 52.34=52.34、寒武纪 199.10=199.10、
招商银行 6.82=6.82），改用自算只是为了让每一行的口径都可追溯。

**每一行的计算依据都摆在明面上**：成分股表里有「财报期 / 披露日」两列，
标明该行用的是哪一期报告、那家公司何时披露的。例如：

```
代码      名称        PE      增速%    财报期        披露日
300308  中际旭创    52.34    200.4   2026-06-30   2026-08-22
300750  宁德时代    18.34     45.6   2026-06-30   2026-07-25
600519  贵州茅台    19.82     -9.5   2026-06-30   2026-08-15
```

当前基准期分布：`2026-06-30 × 307 家（91%）、2025-12-31 × 31 家（9%）、
2026-03-31 × 1 家`——那 31 家尚未披露中报，自动回退到年报，一目了然。

### 到底用哪份报告算？

**不是固定用某一种报告，而是以「最新已披露的那期」为入口**，随披露进度自动推进：

| 时点 | 入口报告 |
|---|---|
| 4/30 之后 | 当年一季报 |
| 8/31 之后 | 当年半年报 |
| 10/31 之后 | 当年三季报 |
| 次年 4/30 之后 | 上年年报 |

今天是 2026-09-09，所以入口是 **2026 年半年报**。界面「增速的计算依据」会列出
本次实际用到的每一份报告及其用途，例如：

```
2026-06-30  2026 年半年报   本期累计
2025-12-31  2025 年年报    上年年报
2025-06-30  2025 年半年报   去年同期累计
2024-12-31  2024 年年报    前年年报
2024-06-30  2024 年半年报   前年同期累计
```

即 **2 份半年报 + 2 份年报 + 1 份本期半年报，共 5 份**。
所以既不是"只用半年报"也不是"只用年报"，而是拼出最近 12 个月。

> 顺带一提：**持仓**只能用半年报/年报（一季报、三季报只披露前十大重仓），
> 这与增速可选任意一期报告是不同的两件事。

### PIT 对齐：按每家公司真实披露日，而不是法定截止日

各公司披露财报的时间差得很多，实测 2026 半年报：

```
2026-07 披露   84 家      ← 最早 7 月中
2026-08 披露 5914 家
2026-09 披露    2 家
```

若统一按 8/31 的截止日计，早披露公司的数据会被白白压一个多月；
若统一按最早披露日计，又会把未披露公司的未来数据算进去（前视偏差）。

本工具用东财 `NOTICE_DATE`（真实公告日期）做 **PIT（point-in-time）对齐**：
每家公司各自判断，只用基准日之前**已公开**的财报。

盘后披露（A 股 18:00 前后整批出报）的公告日会被记成次日，所以生效日取
`NOTICE_DATE` 与入库时间戳 `EITIME` 里**较早**的那个——财报当晚就已公开，
分析当晚就该用上（药明康德 2026 三季报：公告日 10-27，实际 10-26 17:15 入库）。

```
基准日        已可用公司   基准期分布
2026-08-10     339/339    2026半年报×7   2026一季报×216   2025年报×116
2026-08-20     339/339    2026半年报×74  2026一季报×166   2025年报×99
2026-08-31     339/339    2026半年报×307 2026一季报×1     2025年报×31
```

同一天不同公司用不同报告期，这是对的。副作用是**覆盖率更高**了：
沪深300ETF 的有效样本从 189 只提升到 **211 只**——未披露中报的公司会
自动回退到它上一期已披露的 TTM，而不是被当成"无数据"丢掉。

界面「增速的计算依据」会显示当前基准期分布，例如
`2026-06-30 × 307 家（91%）、2025-12-31 × 31 家（9%）`。

> 持仓（基金定期报告）拿不到公开披露日，仍按法定截止日判定，偏保守。

### TTM 净利润的构造

财报是**累计值**，直接用累计同比会有季节性失真，所以用滚动 12 个月：

```
TTM_本期  = 本期累计归母 + 上年年报归母 − 去年同期累计归母
TTM_去年同期 = 去年同期累计 + 前年年报 − 前年同期累计
```

例：2026 中报的 TTM = 2026H1 + 2025年报 − 2025H1。

### 扣非归母净利润（成分股明细的两列）

界面成分股明细额外给出「扣非TTM(亿)」与「上年扣非(亿)」，口径与归母净利润完全对称：

```
TTM 扣非      = 本期累计扣非 + 上年年报扣非 − 去年同期累计扣非
上年同期 TTM  = 去年同期累计扣非 + 前年年报扣非 − 前年同期累计扣非
```

两者共用**完全相同的一组报告期**，因此可以直接相减：差额即非经常性损益
（政府补助、资产处置、公允价值变动等）。差额占扣非超过 30% 时该格标黄。

数据源上有个坑：业绩报表 `RPT_LICO_FN_CPD`（主财报用的那张）只有扣非 **EPS**
（`DEDUCT_BASIC_EPS`），没有扣非净利润金额。金额要到利润表
`RPT_DMSK_FN_INCOME` 取 `DEDUCT_PARENT_NETPROFIT`，而这张表用 `REPORT_DATE`
过滤（不是 `REPORTDATE`），两套字段名不能混。

- 覆盖：2026-06-30 期实测 5583 家 A 股。
- 港股：HKFRS 不要求拆分非经常性损益，没有扣非口径。明细表改用**股东应占溢利**
  （即归母净利润）代替，数值后带 `†` 标记 —— 看到 † 就当它是归母净利润，
  不要和 A 股的扣非横着比。港股财报只披露中报/年报，这两列的更新节奏也比 A 股慢。
- A 股某期扣非缺失时保持 `—`，不做替代：「有口径但没抓到」和港股「根本没有这个口径」
  是两件事，混在一起就分不清数据到底可不可比。
- 存储：单独补拉后 `UPDATE fin SET deduct_np=?`，与主财报分开，老库命中缓存时
  只补这一列、不重拉整期财报；上游失败会冷却一小时再试。

### 增速口径可切换

- **TTM 净利同比**（默认，稳健）：滚动 12 个月，抹平季节性与单季波动
- **最新报告期累计同比**（灵敏）：直接用东财 `SJLTZ`，反映最新边际变化

### 有效样本与 PEG 的成立条件

组合增速为**全口径加权**（见上节），不筛样本。以下状态只影响**个别指标**的
可用性，不影响增速：

| 状态 | 含义 | 影响 |
|---|---|---|
| `no_pe` | 亏损 / 微利，PE ≤ 0 | 不进 PE 的整体法；增速照常计入 |
| `no_growth` | 增速 ≤ 0 或缺失 | 不进 PEG（PE÷负增速无意义）；增速照常计入 |
| `no_quote` | 停牌无行情 | 无法算 PE；增速照常计入 |

- 「有效样本」= PE>0 且增速>0，仅用于 **PEG 的成立条件、中位数 PEG、
  加权平均 PEG**，以及覆盖率统计（`coverage`）。
- 增速 ≤ 0 时 PEG 留空，但增速本身照常展示；此时应改用 PB / PS / EV 等
  绝对估值指标。
- `g_all` 为等权对照；与加权增速相差 >5pct 时提示「组合权重集中，
  增速受大权重股主导」，用于判断口径敏感度，而不是选择性偏差。

## 扫描性能与稳定性

曾经「点开始扫描 → 卡在初始化几小时」，根因是五个问题叠加，均已修复：

| # | 问题 | 修复 |
|---|---|---|
| 1 | `/api/scan/start` 在处理线程里同步拉 ETF 列表，前端 `await` 不到响应就不启动轮询，界面永久停在「初始化」 | 启动接口只置状态立刻返回，拉列表移入工作线程；前端先起轮询再发启动请求 |
| 2 | 拉行情 + 财报（约 300 次请求）全部在第一次进度回调之前完成，期间界面零反馈 | 每个准备阶段都上报 stage 文案；财报阶段按**页**粒度上报 |
| 3 | `retries=3` 配 4 个行情域名，队尾的 `push2delay` **永远轮不到**；主节点 502 时一路重试到超时 | 尝试次数取 `max(retries, 节点数)`，确保每个节点都试到；成功的节点动态置顶 |
| 4 | 无节制并发打东财被限流，连接被掐断后每次 40s 超时 ×4 次重试，指数级恶化 | 全局令牌桶限流 ~9 req/s；超时 20s、重试 3 次并带回退 |
| 5 | 逐只串行抓持仓，一只卡住整批停摆 | 持仓并发抓取（默认 5 路），单只失败不影响其他；支持中途取消 |

另外几项优化：

- 财报只拉 TTM 需要的 **5 期**（原本 10 期），请求量减半
- 跳过尚未到来的报告期（如 9 月份不再请求今年 12 月的年报）
- ETF 列表加 7 天长期备份，上游临时不可用时降级而非直接失败
- 行情/财报缓存失效后若请求失败，回退到过期数据（stale-while-error）

## 历史 PEG（8.6 年，年/季/月柱状图）

> **上限说明**：东财个股每日 PE 最早只到 **2018-01-02**（起始日填更早也只返回
> 2109 条）。所以"近 10 年"做不到，实际可用约 **8.6 年**，界面下拉里标注为
> 「全部可用」。持仓与财报可回溯更早（2016 / 2014），但 PE 卡住了上限。

界面上：分析结果下方选区间 → 点「回填历史」→ 出**柱状图**，
可按 **年 / 季 / 月** 切换桶，指标可切
**PEG / PE / 增速% / 扣非增速% / 扣非PEG / 归母净利 / 扣非净利 / PS / 股息率**。
柱高取该桶**最后一个交易日**的值（期末估值），悬停显示区间极值与天数。

### 历史序列的双口径（v10）

同一个历史日期，用哪套持仓去算，结果完全不同：

| 口径 | 持仓 | 适用场景 | 前视偏差 |
|---|---|---|---|
| **fixed（默认）** | 全部历史统一用**最新一期持仓** | 判断「当前这篮子股票历史上贵不贵」；柱子间可比、净利与增速分母同源 | 有（2022 年的组合并非当时实际持有） |
| **pit** | 每期用当时已知的持仓 | 复盘「当时市场看到的估值」、策略回测 | 无，但柱子含调仓影响 |

fixed 口径下 013816 实测：

```
2025-08  归母净利 13.82 亿    ← 用 2026-06-30 的 69 只持仓算 2025H1
2026-08  归母净利  8.84 亿
2026-08  增速 = 8.84 / 13.83 − 1 = −36.07%
```

三个数字互相印证，柱子 ÷ 分母 = 增速。而 PIT 口径下 2025-08 用的是
**2024 年报的 53 只持仓**，柱子只有 0.61 亿，与 2026-08 的 8.84 亿不可比
——这正是「归母净利涨了、增速却是负的」的来源（持仓换了，不是同一批股票）。

> **fixed 的持仓有前视**：它回答「如果一直持有今天这篮子股票，历史估值/盈利如何」，
> 不能用于回测收益；只适合估值分位与周期判断。要看当时市场真实可见的估值，切到 PIT。
>
> 两套序列独立存储（`etf_daily.basis`），回填时一次双写、零额外请求；
> 增量判定与口径版本（`etf_calc_version.basis`）也各自独立。
> 前端图表右上角可切换，AI 报告默认 fixed 并在口径章节注明前视性质。

### 「增速%」的口径：全口径 + 持仓权重加权

```
增速% = Σ(w·TTM归母净利) / Σ(w·上年同期TTM归母净利) − 1
```

- **不筛样本**：亏损股、负增长股全部计入。旧的「只留 PE>0 且正增长」口径
  会把负增长整段剔除，增速被系统性抬高（013817 实测正增长样本 +26.2%
  vs 全样本等权 −108.1%，方向完全相反）。
- **乘持仓权重**：净利润是绝对额，不能等权相加（与扣非净利同一条规则）。
- 柱高取该桶最后一个交易日的值，TTM 滚动 12 个月，**不是当季/当月增速**。
- PEG 只在加权增速 > 0 时有值；增速 ≤ 0 时柱状图照常画，PEG 留空。
- 历史序列额外存 `g_all`（等权简单相加）作对照，差额反映持仓集中度。

### 「扣非净利(亿)」的口径：全口径 + 持仓权重加权

和 PEG/PE 不同，这个指标是**绝对金额**，因此有两条必须说明的规则：

```
扣非净利 = Σ(持仓权重% ÷ 100 × 成分股 TTM 扣非归母净利润)
```

- **TTM 滚动 12 个月**：任何桶（年/季/月/日）取的都是该桶最后一个交易日的
  TTM 快照，不是当季/当月单期利润。A 股只披露季度累计财报，曲线呈阶梯状，
  只在财报披露日（PIT 生效日）跳变。
- **不筛样本**：亏损股、负增长股全部计入。PE/PEG 用的「PE>0 且增速>0」是
  估值样本口径，不用于这条曲线——否则「亏损收窄」的公司会被放进来，
  其巨额负扣非把合计打成大负数（013817 实测曾因此一天假跳 332 亿）。
- **必须乘权重**：净利润是绝对额，直接相加等于假设每只成分股都 100% 持有，
  会系统性高估一个量级（013817：简单相加约 165 亿 vs 加权后十几亿）。
- 港股不披露扣非、A 股某期缺扣非时，用**归母净利润**顶上（与成分股明细的 † 一致）。
- 因此图表值**不能**与成分股明细表里的「扣非TTM(亿)」（逐股 100% 口径）直接相加对比。

### 「归母净利(亿)」与「扣非增速% / 扣非PEG」曲线

- **归母净利(亿)** = `Σ(w·TTM归母净利)`，与扣非净利完全同一套加权规则，
  两者相减即非经常性损益。
- **扣非增速%** = `Σ(w·扣非TTM) / Σ(w·上年扣非TTM) − 1`，全口径加权，
  与归母增速对称；港股/缺扣非用归母顶上。
- **扣非PEG** = 扣非PE ÷ 扣非增速，仅扣非增速 > 0 时有值。亏损周期里
  这条曲线大面积为空是**正常现象**（行业扣非为负），不是数据缺失。
- 两条 PEG 曲线并列看：归母 PEG 反映「报表利润的性价比」，扣非 PEG 反映
  「主业利润的性价比」。归母 PEG 很低而扣非 PEG 缺失/很高时，说明利润
  主要来自非经常性项目。

**沪深300ETF 实测（2018-01-02 ~ 2026-09-10，2109 个交易日）**：

```
按年（9 桶）：
2018  PE=10.14  PEG=0.573   ← 估值低位
2019  PE=12.48  PEG=0.749
2020  PE=21.27  PEG=0.774   ← 抱团泡沫，PE 飙升
2021  PE=16.08  PEG=0.487   ← 盈利高增消化估值
2022  PE=12.29  PEG=0.594
2023  PE=12.03  PEG=0.861
2024  PE=14.19  PEG=1.247   ← PEG 最贵的一年

```

技术要点：

| 环节 | 处理 |
|---|---|
| 个股每日 PE | `RPT_VALUEANALYSIS_DET`，**分页拉全历史**（2109 天 = 3 页/只） |
| 每日持仓 | 21 份历史定期报告（2015 起每年半年报+年报），已入库直接命中 |
| 每日增速 | 44 期财报（2015 起），逐只按真实披露日 PIT 对齐 |
| 回退链 | 每个季度都是基准期，区间越长基准期越多，否则早期日期构造不出 TTM 被整段丢弃 |
| 前视防护 | 早于「最旧一期持仓披露截止日」的日期直接跳过 |

**性能**（重要）：

```
首次回填（全网络）   ~870s   拉取 44 期财报 + 21 份持仓 + 560 只个股全历史 PE
重复回填（增量）      2.2s   已算过的日期直接跳过，只有新交易日才计算
```

两个关键机制：

- **增量计算** —— 历史数据不可变（财报定稿、历史 PE 既成事实），
  已入库的日期不重算；扩展区间只补缺失的那段。方法变更时用 `--clear-history` 或 `force=1` 重算。
- **PE 抓取水位** —— 晚上市的股票最早 PE 天然晚于请求起点，只看日期范围会永远重拉；
  水位表记录「最早从哪天问过上游」，问过即跳过。

```bash
python run.py --backfill 510300 --days 3650  # 命令行回填全部可用历史
python run.py --history 510300               # 查看日线序列
python run.py --clear-history 510300         # 清空（方法变更后强制重算）
```

### 全市场 PE 初始化（可选，但建议做一次）

回填的耗时大头是「逐只拉取成分股的历史 PE」——每只固定 3 次请求，
且不同 ETF 之间的成分股高度重叠，等于反复付同一笔钱。

`--init-pe` 会一次性把全市场约 5600 只 A 股 2018 年以来的每日 PE / 市值 / 收盘价拉进本地库：

| | 初始化前 | 初始化后 |
|---|---|---|
| 单只 ETF 全区间首次回填 | ~37 分钟 | **~5 分钟** |
| 拉 PE | 每只 ETF 各付一次 | 0（全市场共用一份） |
| 数据库体积 | ~300 MB | ~1.5 GB |
| 首次耗时 | — | 约 1.5~2 小时（可中断续传） |

中断后重跑会自动跳过已拉取的部分（`pe_fetch_log` 水位）。
每天新增的数据由 `ensure_market_pe()` 自动补一天，约 5 秒。

```bash
python run.py --init-pe     # 带进度条，Ctrl+C 中断后重跑继续
python run.py --store       # 查看「PE 初始化进度 1338/5560」
```

Web 界面在「本地数据库 → 全市场 PE 初始化」里有同样的按钮、进度条和取消按钮。

### 一个必须说明的口径修正

做回填时发现原先的 PE 有两个问题，已一并纠正（**数值会变**）：

| 问题 | 原做法 | 现做法 | 影响（沪深300ETF） |
|---|---|---|---|
| 加权方式 | 用**总市值**加权 | 用**基金持仓权重**加权 | PE 11.35 → 18.27 |
| PE 定义 | 行情的**动态 PE**（年化值） | **PE-TTM** | ↑ |

- **总市值 ≠ ETF 持有的那一篮子**：A 股总市值含大量非流通国有股，会把银行等
  低 PE 大市值股权重放大，得到的其实是「全市场口径」PE，与 ETF 实际持仓不是一回事。
- **动态 PE 没有历史序列**：动态 PE = 市值 ÷（最新报告期净利润 × 年化系数），
  是「当下」的口径，历史无从追溯；历史可得的只有 PE_TTM。
  为了让历史曲线和当前值可比，两边统一用 PE_TTM（代价是 PE 滞后 1~2 个交易日，
  对季度级指标完全可接受）。

## 排错

**页面报 `Unexpected token 'U', "Unauthorized" is not valid JSON`**

这个错误不是工具产生的——`Unauthorized` 是**请求在到达本地服务之前被拦截**的响应，
典型来源是浏览器代理、VPN 或安全软件把 `127.0.0.1` 也代理了。

按以下顺序排查：

1. **先确认服务在跑**（最常见的原因就是没在跑）：
   双击 `启动.bat`，或命令行执行 `python run.py`，看到
   `访问地址: http://127.0.0.1:8770` 才算起来。那个黑窗口不能关。
2. 把地址从 `http://127.0.0.1:8770` 换成 **`http://localhost:8770`**
   （很多代理的放行列表里有 `localhost` 却没有 `127.0.0.1`，或反之；
   页面也会自动探测另一个主机名，能通的话会直接给出可点击的链接）
3. 临时关闭 VPN / 代理插件，或在代理设置里放行 `127.0.0.1` 与 `localhost`
4. 自检接口：浏览器打开 `http://localhost:8770/api/ping`，应返回 `{"ok":true,...}`

工具侧已做的加固：所有接口（含 400/404/405/500 和未捕获异常）一律返回 JSON，
页面打开时会先自检连通性并在顶部横幅提示，不再抛出裸的 JSON 解析错误。

### 用之前必须知道的四件事

1. **股票仓位** — 场外基金还有现金/债券。工具用 `Σ 持仓权重` 直接给出股票仓位。
   算出的 PE 只是**股票部分**的，不是整个基金的估值。ETF 通常近满仓问题不大，
   主动基金 60~90% 波动，仓位 <70% 会给出警示。
2. **港股可以算，美股不算** — 东财 A 股估值库没有港股的 PE_TTM，
   但工具会用**同一套口径自己算**：`PE = 当日总市值 ÷ 当日已披露的最新 TTM 股东应占溢利`
   （与 A 股的 `mktcap / np_ttm` 完全一致）。持仓里的港股（市场 116）会被识别并参与计算，
   覆盖率分母也只统计「能估值」的部分。
   只有**美股**等确实拿不到数据的市场才不参与，占比 >15% 时会提示。
   例：易方达蓝筹精选 90 只 A 股 + **17 只港股（占 25%）**，港股部分需要
   先执行「港股数据初始化」才有数据（详见下文）。
3. **ETF 联接 / FOF 不适用** — 它们持有的是其他基金而非股票。
   检测到"持仓 ≤15 只且权重 <15%"时会明确提示不适用（如 004752 仓位仅 0.4%）。
4. **主动基金滞后风险更高** — ETF 跟踪指数、持仓稳定；主动基金季度间可能大幅调仓。
   指数型/增强指数型基本等价 ETF，**主动股票/混合型只能当粗略参考**，界面会给出提示。

> 批量扫描仍只做场内 ETF（场外基金 2.8 万只逐个穿透不现实）。单只分析没有限制。

## 历史盈利预测（分析师预测的时序）

成分股明细里**点任意一行**，会弹出该股的历史预测：一致预期走势、近 30/90 天的上调下调家数、逐篇研报明细。

数据来自东财研报中心，实测全市场 **148,506 篇 / 4,865 只**（2017-01 起，占用约 53 MB）：

```bash
python run.py --sync-reports    # 首次 3~5 分钟；之后每次只补当年，约 5 秒
```

Web 界面在「本地数据库 → 研报数据同步」里有同样的按钮、进度条与取消按钮。

表结构 `report` 每篇研报一行，关键是 `year_1/2/3` 存**绝对财年** —— 接口的「今年 EPS」随发布年漂移，不换算成绝对年份就做不了跨年对比。

### 三个口径

**一致预期时序**：同一机构在同一个月内只取最新一篇，再对机构取算术平均。不能直接对所有研报求平均 —— 不同机构发研报的频率差好几倍，频次高的会系统性主导均值。

**上调/下调家数**：每家机构比较「最后一篇」与「它上一篇」对同一财年的 EPS，变动超过 0.5% 才算调价（避免把四舍五入当修正）。

**覆盖度要分两个口径**：`n_org` 是发过研报的机构数，`n_org_fc` 是其中给了分年度预测的机构数。银行股常有大量只给评级、不填 EPS 的研报，混在一起会让覆盖度虚高（平安银行 227 篇 / 25 家机构，只有 5 家给了预测）。

**喂给 AI 的报告不做聚合**：「复制给 AI」里前二十大成分股按机构分组，每家列出**最近 4 篇**（近 24 个月）研报的预测，并标出每篇相对该机构上一篇对同一财年的变化（↑5.2% / ↓3% / 持平），不给平均值。

```
| 机构 | 日期 | 评级 | 目标价 | 2025E | 2026E | 2027E | 2028E |
|---|---|---|---|---|---|---|---|
| 群益证券 | 2026-09-23 | 增持 | 1200.00 | — | 30.13 (持平) | 56.17 (↑5.6%) | 92.07 (↑12.2%) |
| 〃 | 2026-04-17 | 增持 | 1000.00 | — | 30.13 (↑36.0%) | 53.18 (↑42.3%) | 82.05 (↑76.4%) |
| 〃 | 2026-04-01 | 增持 | 650.00 | — | 22.15 (↑9.7%) | 37.36 (↑28.3%) | 46.52 |
| 〃 | 2026-03-02 | 增持 | 700.00 | — | 20.19 (↑11.5%) | 29.13 (↑15.5%) | — |
```

20 家机构里 12 家给 30 元、8 家给 18 元，均值 25 元看着一致，实际是两派观点——平均值恰好把这个信息抹掉了。弹窗里的折线仍用均值（那是画图需要），但文本报告给的是原始分歧与逐次修正。

### 打开弹窗时自动补最新研报

点开弹窗会**先用库里的数据秒开**，同时在后台问一次上游「这只股票有没有比库里更新的研报」：

```
正在检查最新研报…  →  发现 1 篇新研报，正在拉取并刷新…  →  ✓ 已拉取 1 篇最新研报（最新 2026-09-21）
```

- 有更新时只拉增量（通常 0~2 篇、1 个请求），拉完自动重渲染弹窗内容；
- 没有更新则显示「已是最新（截至 X）」，3 秒后淡出；
- 同一只股票 **5 分钟内不重复检查** —— 研报不是秒级更新，反复点弹窗不该反复打上游；
- 库里完全没有这只股票时，退回从 2017 年起全量拉（单次最多 20 页）；
- 港股/美股直接提示「仅 A 股有研报数据」，不发请求。

弹窗顶部还有一排**财年标签**。研报普遍只给「今年 / 明年」两年预测，某个财年的曲线要等它变成「明年」时才会密集出现 —— 2026E 在 2025-04 之前没有任何覆盖，所以默认视图看着只有一年多。勾上旧财年（2024E / 2025E）可以把 x 轴拉回到 2024 年初：

```
茅台    2024E   2024-04 ~ 2024-12   93.47 → 81.09
        2025E   2025-01 ~ 2025-12   80.97 → 74.25
        2026E   2025-04 ~ 2026-09   89.13 → 65.14
```

### 与 F10 一致预期的分工

| | `cons_forecast`（F10） | `report`（研报库） |
|---|---|---|
| 内容 | 每家机构最新一版 | 每篇研报，全历史 |
| 用途 | 前瞻 PE / 前瞻 PEG 的即时计算 | 看预测怎么变、算修正 |
| 更新 | 3 天 TTL | 往年一次、当年每日 |

### 边界

- **仅 A 股**：港股/美股没有免费的逐篇研报预测（实测东财港股研报 `hits=0`）。
- 2017 年之前接口不提供。
- 目标价字段大多为空（`indvAimPriceT`），只有部分研报填写。

## 港股支持

### 为什么港股要单独一套

东财的估值库 `RPT_VALUEANALYSIS_DET`（A 股在用的那个）**完全不含港股**，
`SECURITY_CODE` / `SECUCODE` 两种写法都查不到，也没有港股专用估值报表。
所以 A 股那套「直接下载历史 PE_TTM」在港股走不通，只能自己算：

```
PE = 当日总市值 ÷ 当日已披露的最新 TTM 股东应占溢利
```

这与 A 股 `mktcap / np_ttm` **同一个公式**，因此计算层几乎没有特例分支。
接口调研的全部细节（含已排除的方案与实测样本）见 [`docs/hk_api.md`](docs/hk_api.md)。

### 双库

| | A 股库 `etf_peg.db` | 港股库 `etf_peg_hk.db` |
|---|---|---|
| 存什么 | 财报、ETF 持仓、ETF 名录、个股每日估值、每日 PEG 结果 | 港股财报、港股每日行情/市值 |
| 不存什么 | — | 基金持仓与结果（一只基金的 PEG 可能同时含 A 股和港股，拆开存反而要跨库 join） |

两个库**同一个 schema、同一个 `Store` 类实例化的两份**，只是数据不同。
代码里按持仓条目的 `market` 字段自动选库（`store.market_of`），对上层透明；
模块级 `store.xxx(...)` 仍然默认走 A 股库，几十个既有调用点一行没改。

### 用法

```bash
python run.py --init-hk        # 命令行（带进度条，Ctrl+C 中断后重跑继续）
python run.py --store          # 查看「港股初始化进度 21/2813」
```
Web 界面在「本地数据库 → 港股数据初始化」里有按钮、进度条、取消和覆盖度。

| 项 | 估算 |
|---|---|
| 有效港股只数 | 约 2,800 只（清单 4685 条里有权证等非股票，已用财报过滤） |
| 首次初始化 | **40~60 分钟**，可中断续传 |
| 港股库体积 | 约 **0.8 GB** |
| 每日增量 | 1 次全市场快照，约 5 秒 |

### 港股的口径差异（看结果时要知道）

- **财报按各公司自身财年处理**：港股财年截止日不统一（12/3/6/9 月年结都有），
  同一个报告期里混着不同财年公司的报告（如 03-31 期 = 12 月年结公司的自愿
  一季报 + 3 月年结公司的法定年报）。工具拉取全部四个季度期，用每份财报的
  `REPORT_TYPE` 识别跨度，按公司财年构造 TTM——3 月年结公司不再遗漏。
- **没有真实披露日**：港股接口不提供公告日，PIT 对齐退回法定披露期限
  （年报 +4 个月、中报 +3 个月、季报 +2 个月，HKEX 规则，保守口径）。
  只披露中报+年报的公司，其增速曲线是半年一跳的阶梯状。
- **不需要换汇**：整体法 `PE = Σw / Σ(w/PE_i)` 中 `w` 是基金披露的人民币权重占比，
  PE 无量纲，港股用港币口径、A 股用人民币口径可以直接混算。
- **只采用港币记账的公司**：市值按港币算，净利若用美元/人民币记账会导致 PE 整体错位，
  这类公司（约占 1%）会被跳过并在日志里计数。
- **行情快照可能滞后**：港股现价/市值来自库里最近一次全市场快照。上游 push2 被限流时
  不会把港股估值整块清空，而是退回最近一份**完整**快照，页面顶部单独标注
  「港股行情 YYYY-MM-DD」；只拉到第一页的残缺清单（100 只）既不写入也不缓存 ——
  否则全市场快照只剩 100 只，其余港股统统变「无行情」。

## 已知局限

- **持仓是季度数据，不是实时的。** 真正的每日持仓要去解析交易所的 PCF 申赎清单
  （上交所 `sse.com.cn` / 深交所 `szse.cn`），格式不统一且接口不稳定，性价比不高。
- **PE-TTM 滞后 1~2 个交易日**：东财估值库 T+1 更新。想要盘中实时的 PE 只能用
  行情接口的「动态 PE」，但那与历史序列口径不一致，故未采用。
- **回填区间受财报深度限制**：构造 TTM 需要前 2 年的财报，回填 2 年以上会
  自动拉取更多报告期（一次性，永久入库），首次会慢一些。
- **港股财报按各公司自身财年处理**（12/3/6/9 月年结全覆盖，年报/中报为主、
  部分公司有季报）。港股没有真实披露日，PIT 按财报类型的法定期限
  （年报 +4 个月、中报 +3 个月、季报 +2 个月）保守对齐；只披露中报+年报
  的公司其增速曲线是半年一跳的阶梯状。
- **`push2his`（港股日 K 所在的域名）限流敏感**：批量抓取时容易被掐连接，
  代码里已做 HTTPS/HTTP 双协议回退与退避重试，并支持断点续传。
- **非 12-31 财年的港股公司**（如 3/31 年结）TTM 会跨错年，目前作为已知限制。
- **增速是历史值，PEG 本质是后视镜。** 更严谨的 PEG 应该用一致预期增速，
  免费源拿不到券商预测数据（Wind/朝阳永续均需付费）。
- **高增速行业（如半导体）的 PEG 会失真。** 增速 100%+ 时 PEG 天然很低，
  工具会在增速 >100% 时给出提示，此时应结合绝对 PE 与行业景气度判断。
- 债券/商品/货币 ETF 无股票持仓，会直接提示无数据。
